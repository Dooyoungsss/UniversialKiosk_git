--------------------------------------------------------------
1. 카메라를 GENERAL WEBCAM으로 변경
--------------------------------------------------------------
 - 이 컴퓨터에 연결된 카메라: 0번 = 720p HD Camera, 1번 = GENERAL WEBCAM
 - config.py 의 CAMERA_INDEX 를 1 로 바꿔 GENERAL WEBCAM 을 사용합니다.
 - 주의: 카메라 번호는 연결 순서에 따라 바뀔 수 있습니다. 대회장에서 다른 노트북이나
   다른 USB 포트를 쓰면, 화면 오른쪽 위 카메라 미리보기가 원하는 카메라인지 꼭 확인하세요.
 - (10번에서 추가) 설정한 번호의 카메라가 없으면 다른 카메라를 자동으로 찾아 씁니다.
   이때 콘솔에 "[카메라] 설정한 1번 카메라가 없어 0번 카메라를 사용합니다."가 찍힙니다.


--------------------------------------------------------------
2. 시각장애인 음성 안내: "네" 인식 개선
--------------------------------------------------------------
 [문제] "네"라고 말해도 음성 주문으로 넘어가지 않았음
 [원인]
  - 질문 음성(약 9초)이 끝나기 전에(5초) 마이크가 켜져서, 키오스크 자신의 목소리를
    '주변 소음'으로 재고 듣기 기준을 너무 높게 잡음 → 짧은 "네"를 놓침
  - 한 번 못 들으면 다시 듣지 않음
 [바뀐 점]
  - 안내 음성이 '완전히 끝난 뒤' 0.5초 쉬었다가 마이크를 켭니다.
  - 못 들었거나 다른 말이 들리면 최대 5번까지 다시 듣습니다.
  - "네·내·예·넵·응", "잘 안 보여요", "yes", "是" 등을 '네'로 알아듣습니다.
    ("괜찮네요"처럼 '아니요' 뜻이 섞인 말은 '아니요'로 봅니다.)
  - 5번 모두 못 알아들으면 "화면의 큰 네 버튼을 누르시거나, 엄지와 검지 끝을 맞대어
    집어 주세요"라고 소리로 안내합니다.
  - 안내창이 '네/아니요'를 듣는 동안에는 나이 인식에 따른 화면 전환(과 그 안내 음성)을
    잠시 미룹니다. (전환 안내 소리가 마이크에 섞이는 것 방지)
  - 음성 주문 창의 자동 마이크도 같은 방식으로, 안내가 끝난 뒤에 켜집니다.
 [주의] 말을 글자로 바꾸는 기능은 Google 음성 인식이라 인터넷 연결이 필요합니다.

3. 시각장애인 안내창이 계속 다시 뜨던 문제
--------------------------------------------------------------
 [원인]
  - 고개를 돌려 얼굴이 '잠깐만' 안 잡혀도 손님이 떠났다고 판단하고 안내를 다시 준비함
  - 이미 안내창·음성 주문 창이 떠 있는지 확인하지 않고 새 창을 겹쳐 만듦
 [바뀐 점]
  - 얼굴이 8초 이상 '계속' 안 보일 때만 다음 손님으로 봅니다.
  - 안내창이나 음성 주문 창이 열려 있으면 새 안내창을 만들지 않습니다.

4. 메뉴·장바구니 목록을 손가락(터치)으로 밀어서 넘기기
--------------------------------------------------------------
 - 스크롤바를 잡지 않아도, 목록 아무 곳이나 위/아래로 밀면 관성 있게 넘어갑니다.
   (마우스로 끌어도 똑같이 동작)
 - 6mm 이상 끌었을 때만 스크롤로 보고, 짧게 톡 치면 지금처럼 메뉴 담기·+/− 버튼이
   눌립니다.


--------------------------------------------------------------
5. 선택은 '집게 손'으로만 — 화면의 모든 버튼을 누를 수 있음
--------------------------------------------------------------
 [집게 손] 엄지 끝과 검지 끝을 맞대고 잠깐(6프레임) 유지
 - 손 커서 아래에 있는 것을 손가락으로 누른 것처럼 클릭합니다. 누를 수 있는 것:
   메뉴 카드, 카테고리 탭(버거·사이드·음료), 세트로·음성으로 주문 버튼,
   장바구니 +/−/✕, 전체 비우기, 결제하기, 위쪽 English·고대비·소리 안내 버튼,
   시연 도구 버튼, 환영 화면의 주문 시작·음성으로 주문 버튼
 - 안내창(네/아니요): 커서가 가리키는 버튼을 누릅니다. 아무 버튼도 가리키지 않으면 '네'.
   (눈이 불편한 손님은 커서를 볼 수 없기 때문)
 - 음성 주문 창: 커서가 가리키는 버튼(마이크·예시 문장·취소·주문 분석)을 누릅니다.
   버튼을 가리키지 않았으면 입력된 문장으로 바로 '주문 분석'을 합니다.
 - 메뉴 화면에서 빈 곳을 집으면 "누르고 싶은 메뉴나 버튼 위에 커서를 올린 뒤 집게 손으로
   집어 주세요"라고 안내합니다.
 - 예외: '손동작 켜기/끄기' 버튼은 집게로 눌리지 않습니다. 손동작으로 손동작을 꺼 버리면
   다시 켤 방법이 터치밖에 없어서, 손으로만 쓰는 손님이 조작할 수 없게 되기 때문입니다.
 - 결제하기 버튼도 이제 집게 손으로 눌립니다(예전에는 실수 결제를 막으려고 2초 멈추기로만).
 - [정확도 보정] 실제 카메라 기록을 보니 집게 인식은 잘 됐지만, 작은 버튼(장바구니 +/−/✕)은
   커서가 살짝 빗나가 옆의 글자나 빈 곳을 집는 경우가 많았습니다. 그래서
   · 집게를 한 곳에 버튼이 없으면 가까운(70px 안) 버튼을 대신 누릅니다.
     단, 결제하기·전체 비우기는 실수 방지를 위해 정확히 가리켰을 때만 눌립니다.
   · 손가락을 오므리는 동안 손바닥 중심이 움직여 커서가 미끄러지므로,
     집게를 시작하기 0.25초 전의 커서 위치로 클릭합니다.
   · 화면 맨 아래 버튼(전체 비우기·결제하기)까지 커서가 잘 안 내려가서, 손을 조금만
     내려도 화면 맨 아래에 닿도록 조준 영역(AIM_ZONE 아래 끝 0.80 → 0.72)을 바꿨습니다.
 - 주먹·엄지척은 더 이상 선택으로 쓰지 않습니다. (잘못 인식돼 엉뚱하게 눌리는 것 방지)
 - 주먹을 쥐면 엄지 끝이 접힌 검지 옆에 붙어 집게처럼 보일 수 있어서,
   검지가 앞으로 뻗어 있을 때만 집게로 인정합니다.
 - 그대로 유지되는 선택 방법: 커서를 2초 멈추기(드웰), 화면 터치
 - 화면·음성 안내 문구(한국어·영어·중국어)와 시연 도구의 '담기' 버튼(🤏)도
   집게 손 기준으로 바꿨습니다.

6. 손동작으로 위/아래 스와이프 → 목록 넘기기
--------------------------------------------------------------
 - 손바닥을 편 채 위로 빠르게 휘두르면 → 목록의 아래쪽 내용이 올라옵니다.
   (손가락으로 화면을 위로 미는 것과 같은 방향)
 - 아래로 빠르게 휘두르면 → 다시 위쪽 내용으로 돌아갑니다.
 - 커서가 장바구니 위에 있으면 장바구니를, 아니면 메뉴 목록을 넘깁니다.
 - 한 번에 보이는 높이의 70%씩 부드럽게 넘어갑니다.
 - 좌우 스와이프(카테고리 넘기기)는 그대로입니다. 대각선으로 휘두르면 더 크게 움직인
   방향 하나만 인정합니다.
 - 커서를 옮기려고 손을 천천히 움직이는 것은 스와이프로 보지 않습니다.
   (빠르게 휘두를 때만 인정)
 - [인식 개선] 처음에는 '한 프레임(약 0.05초) 사이에 크게' 움직여야 해서 거의 인식되지
   않았습니다. 이제는 0.35초 동안 손바닥이 손 크기만큼 위나 아래로 움직이면 인정합니다.
 - 휘두르는 동안 커서도 같이 움직이므로, 휘두르기 '전' 커서 위치로 메뉴/장바구니를 고릅니다.
 - 목록이 한 화면에 다 보여서 넘길 내용이 없으면 "넘길 내용이 없어요"라고 알려 줍니다.

7. 세로 모니터 해상도에 맞춰 화면 크기 자동 조절
--------------------------------------------------------------
 [문제] '음성 도움 안내' 창이 너무 커서 화면 밖으로 튀어나감
 [원인] 화면은 세로 1080×1920(스탠바이미 원래 해상도) 기준으로 만들었는데, 지금 세로
        모니터가 768×1366 해상도로 연결돼 있음. 안내창은 폭이 900으로 고정이라
        768 폭 화면을 넘어감(메인 화면·음성 주문 창도 같은 이유로 넘칠 수 있었음).
 [바뀐 점]
  - 프로그램을 켤 때 세로 모니터 크기를 확인해서, 1080×1920보다 작으면 화면 전체를
    같은 비율로 줄입니다(지금 모니터: 0.711배). 디자인 모양은 그대로이고 크기만 줄어듭니다.
  - 안전장치로, 안내창·음성 주문 창은 메인 화면보다 넓어지거나 길어지지 않습니다.
  - 일반·실버·어린이·고대비 4가지 모드 모두에서 두 창이 화면 안에 들어오는 것을
    실제 모니터로 확인했습니다.
 [참고] 스탠바이미의 원래 해상도는 1920×1080입니다. Windows 디스플레이 설정에서 세로
        모니터 해상도를 1920×1080(세로 방향)으로 바꾸면 줄이지 않은 원래 크기로 더
        선명하게 보입니다. 어느 해상도든 프로그램이 알아서 맞춥니다.

8. 음성 인식 마이크를 USB 마이크(USBAudio1.0)로 고정
--------------------------------------------------------------
 - config.py 의 MIC_NAME = "USBAudio1.0" 으로, Windows 기본 마이크가 블루투스 헤드셋 등으로
   바뀌어도 키오스크는 항상 이 USB 마이크로 듣습니다. (credio 마이크로 추정)
 - 이름에 맞는 마이크를 못 찾으면 Windows 기본 마이크로 대신 듣고, 콘솔에 안내를 찍습니다.
 - 다른 마이크를 쓰려면 MIC_NAME 에 장치 이름 일부를 넣으세요. 예) "GENERAL WEBCAM"
 - (추가) 음성 안내 스피커도 이름으로 고정: SPEAKER_NAME = "BS-05" (블루투스 스피커).
   Windows 기본 출력이 바뀌어도 안내는 BS-05 로 나갑니다. 블루투스가 끊기면 기본 스피커로
   대신 내보내고 콘솔에 "[스피커] …찾지 못해…"를 찍으며, 다시 연결되면 자동으로 BS-05 로
   돌아갑니다. (통화용 'Hands-Free' 장치는 음질이 나빠 쓰지 않음)


--------------------------------------------------------------
9. 실제 사용 테스트 후 개선
--------------------------------------------------------------
 (1) 음성 인식이 한 번 실패하면 다시 안 되던 문제
  - 음성 주문 창에서 못 알아들으면 이유를 말해 준 뒤 자동으로 다시 듣습니다(최대 3번).
    3번 모두 실패하면 "마이크 버튼을 누르거나 집게 손으로 눌러 다시 말씀해 주세요"라고 안내.
 (2) 음성 주문 뒤 바로 결제가 안 되던 문제 → 대화식 음성 주문
  - 알아들은 말은 '주문 분석' 버튼 없이 바로 장바구니에 담고, 담은 메뉴·합계를 읽어 준 뒤
    "더 주문하시려면 말씀해 주시고, 결제하시려면 결제라고 말씀해 주세요"라고 하고 계속 듣습니다.
  - "결제할게요"라고 말하거나 창의 '💳 결제하기' 버튼을 누르면 창을 닫고 바로 결제합니다.
    (한 문장으로 "불고기버거 하나 주시고 결제할게요"도 가능)
  - 영어로 주문하면 다음 말부터는 영어로 먼저 알아듣습니다.
 (3) 드웰(2초 머물기)을 하고 있으면 메뉴가 계속 담기던 문제
  - 한 번 선택한 메뉴·버튼은 커서가 그 밖으로 나갔다 돌아와야 다시 선택됩니다.
    (메인 화면, 안내창, 음성 주문 창 모두)
 (4) 스크롤·집게가 안 되던 문제 → 탄력 조준
  - 원인: 카메라 위치·서 있는 자세 때문에 손이 고정 조준 영역보다 아래에 있어서, 커서가
    화면 맨 아래(맨 아래 줄 버튼)에 붙어 있었음. 그래서 집게를 하면 '소리 안내' 같은 맨 아래
    버튼만 눌리고, 메뉴·장바구니에는 닿지 않았음.
  - 손을 처음 든 위치를 기준으로 커서를 맞추고, 손이 범위 밖으로 나가면 범위가 손을 따라
    갑니다. 카메라 높이·손님 키와 상관없이 화면 위·아래·좌·우 끝까지 닿습니다.
    손이 3초 이상 안 보이면 다음에 손을 든 위치로 다시 맞춥니다.
  - 위/아래 스와이프 기준도 완화(0.45초 동안 손 크기의 0.7배 이상 움직이면 인정).
 (5) 모드가 바뀔 때 메뉴 위치가 달라지던 문제
  - 일반·실버·어린이·고대비 모두 메뉴를 같은 순서·같은 2열로 보여 줍니다.
    모드가 바뀌어도 메뉴 위치는 그대로이고 글자·그림 크기만 달라집니다.
    (예전: 일반은 3열, 실버는 인기 메뉴를 앞으로 재정렬해서 위치가 바뀌었음)
 (6) 영어·중국어 인식이 잘 안 되던 문제
  - 원인: 화면이 한국어면 한국어 인식기로만 들어서, 영어·중국어 말을 "투 치즈버거 플리즈"처럼
    한글로 받아 적었음. (문장 이해 자체는 영어·중국어도 잘 됨: "two cokes" → 콜라 2개,
    "我要一个大汉堡和雪碧" → 빅버거 1개·사이다 1개)
  - 이제 한국어·영어·중국어 인식기에 '동시에' 보내고, 인식기가 매긴 신뢰도 + 주문으로
    이해되는지 + 언어와 글자가 맞는지(예: 중국어 결과에 한자가 있는지)를 함께 보고 고릅니다.
    동시에 보내므로 기다리는 시간은 거의 같습니다.
  - 실제 Google 음성 인식으로 확인: 영어 음성 → 영어 결과 선택(신뢰도 0.86),
    한국어 음성 → 한국어 결과 선택. (영어 음성을 중국어 인식기가 'QQQ'로 받아 적고 신뢰도를
    0.91로 높게 주는 경우가 있어서, 글자가 맞지 않는 결과는 감점하도록 함)
 (7) "결재 해줘"라고 해도 결제가 안 되던 문제
  - 음성 인식이 '결제'를 '결재'로 받아 적는 경우가 있어 '결재'도 결제로 알아듣습니다.
    영어 "that's all", "check out" 도 결제로 인정.
  - 음성 주문 창에서 마지막에 "결제(결재) 해줘"라고 하면 창을 닫고 바로 결제합니다.
 (8) 장바구니 스크롤바 없앰
  - 장바구니의 스크롤바를 숨겼습니다. 손가락으로 밀거나 손동작 위아래 스와이프로 넘깁니다.


--------------------------------------------------------------
10. 전체 점검으로 찾아 고친 버그
--------------------------------------------------------------
 (1) 집게를 쥔 채로 있으면 계속 클릭되던 문제  ★ 가장 중요
  - 집게를 1.5초 쥐고 있으면 0.3초마다 다시 클릭돼 메뉴가 5번 담겼음
    (장바구니에 같은 메뉴가 11개씩 쌓이던 원인으로 보임). 주먹·엄지척도 같은 문제.
  - 이제 한 번 집으면 한 번만 클릭됩니다. 손을 폈다가 다시 집어야 다음 클릭이 됩니다.
 (2) 설정한 카메라가 없으면 바로 '데모 모드'가 되던 문제
  - 다른 컴퓨터·다른 USB 포트에서는 카메라 번호가 바뀔 수 있는데, 1번이 없으면 카메라를
    아예 안 썼음. 이제 0~3번 중 실제로 영상이 나오는 카메라를 자동으로 찾습니다.
  - 프로그램을 켤 때 카메라가 없으면 2초마다 다시 찾아서, 나중에 꽂아도 바로 작동합니다.
 (3) 실행 중 USB 카메라가 빠지면 CPU 를 100% 쓰며 멈춰 있던 문제
  - 영상을 못 읽어도 쉬지 않고 계속 다시 읽었고, 다시 꽂아도 복구되지 않았음.
  - 이제 약 1초 동안 영상이 안 오면 "카메라 연결이 끊겼어요"라고 표시하고 기다리다가,
    다시 꽂으면 자동으로 이어서 작동합니다.
 (4) Windows 화면 배율(125% 등)을 쓰면 화면이 괜히 더 작아지던 문제
  - 모니터 크기를 배율이 적용된 값(예: 1920 → 1536)으로 읽어서 실제보다 작다고 판단했음.
    이제 배율과 상관없이 실제 해상도로 계산합니다.
 (5) 시연 도구의 '담기' 버튼을 집게로 누르면 프로그램이 멈추던 문제
  - '담기' 버튼이 다시 집게 클릭을 부르고, 그게 또 '담기' 버튼을 누르는 무한 반복이었음.
 (6) 결제 중이거나 안내창이 떠 있을 때 손님이 떠난 것으로 처리되던 문제
  - 안내창·결제 화면에서는 '손님 떠남' 판단을 미뤘다가 끝난 뒤 다시 확인합니다.
 (7) 음성 주문 창이 알아듣지 못한 말을 끝없이 다시 듣던 문제
  - 주문으로 이해되지 않는 말도 실패로 세어, 3번이 넘으면 멈추고 버튼 사용을 안내합니다.
 (8) 마이크를 한 번 못 찾으면 다시 꽂아도 계속 못 찾던 문제
  - USB 마이크가 잠깐 빠졌을 때 '없음'을 기억해 버렸음. 이제 들을 때마다 새로 찾고,
    다시 찾으면 콘솔에 "다시 찾았습니다"라고 알려 줍니다(같은 경고는 한 번만 출력).
 (9) 스와이프로 목록을 넘길 때마다 애니메이션이 쌓이던 문제(오래 쓰면 느려짐) → 정리
 (10) 음성 창이 자동으로 들을 때 마이크 버튼이 '듣는 중'으로 바뀌지 않던 문제
 (11) 음성 주문 창에서 드웰을 쓸 때 가끔 오류가 나던 문제(초기값 누락)
 (12) 한 번 결제한 뒤로는 시각장애인 안내를 다시는 묻지 않던 문제
  - 첫 결제 후 '이미 주문함' 표시가 풀리지 않아, 다음 손님이 와도 안내가 뜨지 않았음.
  - 이제 결제를 마치고 첫 화면으로 돌아온 뒤 손동작이 인식되면 "눈이 불편하신가요?"를
    다시 묻습니다(한 번만). 손님이 떠났다가 새 손님이 오면 얼굴 인식으로도 다시 묻습니다.
 (13) 처음에 시각장애인 안내(→ 음성 주문)가 안 뜨던 문제
  - 안내는 '얼굴이 보이는 순간'에만 떴는데, 카메라 각도 때문에 얼굴이 화면 위로 잘리거나
    보였다 안 보였다 하면 안내가 아예 안 떴고, 한 번 놓치면 다시 시도하지 않았음.
  - 이제 첫 화면에서 아직 안 물었으면 손동작(손을 들기만 해도)이 보여도 안내를 띄웁니다.
    화면이 아직 준비 안 된 것처럼 잠깐의 이유로 건너뛰었으면 다음 기회에 다시 시도합니다.
  - 콘솔에 [접근성안내] 줄로 진행 상황이 찍힙니다(얼굴 보임/안내창 띄움/대답/음성 주문 창
    열림, 건너뛰었으면 그 이유). 안 뜰 때 이 줄을 보면 원인을 알 수 있습니다.
 (14) 결제 후 화면 모드가 다음 손님에게 그대로 남던 문제
  - 고대비·실버·어린이 모드로 결제한 뒤 첫 화면으로 돌아오면 일반 모드로 되돌립니다.
    (나이 인식이 같은 손님을 보고 곧바로 다시 바꾸지 않도록 4초 전환 대기도 새로 시작)
  - 결제 없이 시간 초과로 첫 화면에 돌아갈 때는 모드를 바꾸지 않습니다.
 (15) 갑자기 큰 글씨 실버 모드로 바뀌던 문제  ★ 나이 인식 오판의 진짜 원인
  - 8월 29일에 OpenCV 가 5.0 으로 올라갔는데, 5.0 은 나이 모델(Caffe)을 읽는 기능이 없어져
    나이 모델이 아예 안 읽혔음. 그래서 예비용 '얼굴 비율 어림짐작'으로 판단했고, 이 방식이
    젊은 사람·어린이도 노인으로 봐서 실버 모드로 바뀌었음. (화면에는 아무 표시가 없었음)
  - OpenCV 를 4.14 로 되돌리고, requirements.txt 에 "opencv-python>=4.8,<5" 로 고정
    (대회장 컴퓨터에 새로 설치해도 5.0 이 깔리지 않음).
  - 나이 모델을 못 읽으면 콘솔에 [나이인식] 경고와 해결 방법을 찍습니다.
  - 실제 카메라로 확인(같은 사람 132번 판단): 노인 1번, 어린이 100번, 성인 31번
    → 이제 실버 모드로 잘못 바뀌지 않음. 단, 학생을 '어린이(8~12세)'로 보는 경우가 많음.
 (16) 시각장애인 안내창: 실수로 '네'가 되지 않게
  - 버튼이 아닌 빈 곳을 집게로 집었을 때 '네'로 보던 것을 없앴습니다(손을 들고 있다가
    실수로 음성 주문으로 넘어가던 문제). '네'·'아니요' 버튼은 드웰(손 멈추기)·집게로 누를 수 있음.
  - 5번 못 알아들으면 "음성 주문을 원하시면 네 라고 또렷하게 말씀해 주세요"라고 안내한 뒤
    한 번 더 들어 줍니다(예전에는 안내 후 마이크가 꺼져 그 뒤에 말해도 소용없었음).


--------------------------------------------------------------
11. 음성 안내·음성 주문 개선
--------------------------------------------------------------
 (1) 첫 안내 뒤로는 음성 안내 소리가 안 나던 문제  ★ 가장 중요
  - 음성 라이브러리(pyttsx3 2.99)의 버그로 '첫 문장만' 소리가 나고, 그다음부터는 말하지 않고
    바로 끝났음(같은 문장이 처음엔 5.3초, 두 번째부턴 0.14초). 그래서 첫 주문 뒤의 음성 도움
    안내, 담김·결제 안내가 모두 소리 없이 지나갔음.
  - 이제 Windows 음성 엔진(SAPI)을 직접 써서 문장마다 끝까지 읽습니다(시험: 6문장 모두 정상).
  - 콘솔에 [음성안내] (몇 초) 문장 이 찍혀 실제로 말했는지 확인할 수 있습니다.
 (2) 음성 도움 안내에서 "네/아니요"를 못 알아듣던 문제
  - 화면 언어로만 알아들어서, 집게로 언어 버튼이 눌려 화면이 영어·중국어가 되면 한국어
    "네"를 못 알아들었음 → 이제 한국어·영어·중국어로 동시에 알아듣습니다.
  - 주변이 시끄러우면 '말소리 기준'이 올라가 작은 "네"를 말소리로 인정하지 못했음
    → 짧은 대답은 기준 없이 3.5초 동안 녹음해서 인식기에 맡깁니다.
  - USB 마이크(USBAudio1.0)는 입력 볼륨 92%(최대 -1dB)여도 소리가 아주 작게 들어옴
    (같은 스피커 소리: USB 마이크 1, 웹캠 마이크 8,070) → 녹음 소리를 최대 20배까지 키워서
    인식기에 보냅니다. 그래도 마이크에 입을 가까이(10~20cm) 대고 말해야 잘 알아듣습니다.
  - (10/17) 마이크를 "USB MIC"로 바꿈(MIC_NAME = "USB MIC"). 입력 볼륨 82%(19dB, 최대 31dB)로
    USBAudio1.0 보다 훨씬 잘 들림: 조용할 때 300~800, 스피커 '네' 2,254 (USBAudio1.0 은 1).
  - 콘솔에 [음성인식] 줄로 들은 시간·녹음 소리 크기·인식 결과·실패 이유가 찍힙니다.
 (3) 안내 문구
  - 음성 주문 창이 열리면 "음성 주문이 시작됩니다. …"
  - 메뉴를 담으면 "감자튀김이 담겼습니다." / "콜라가 담겼습니다."(받침에 맞춰 이/가)
    음성으로 담으면 "불고기버거 1개, 콜라 2개가 담겼습니다. 지금 합계는 …원입니다."
  - 결제가 끝나면 "결제가 완료되었습니다. 주문 번호는 N번입니다. 감사합니다."
    주문 번호는 한글로 바꿔 읽음: "1002번"은 음성 엔진이 '천 두 번'으로 읽어서
    "천이번"으로 읽게 함(음성 인식으로 되받아 확인: 예전 '천두 번' → 지금 '1002번').
  - 모드가 바뀔 때 "일반 모드입니다", "큰 글씨 실버 모드로 바꿨어요" 같은 음성 안내는 하지 않음
    (화면 위쪽 작은 알림만 표시)
 (4) 음성으로 "결제(결재) 해줘" → 확인하고 결제
  - 담은 메뉴와 합계를 읽어 주고 "결제할까요? 네 또는 아니요로 말씀해 주세요."라고 묻습니다.
  - "네" → 결제. "아니요" → "알겠습니다. 더 주문하시거나, 결제하실 때 결제라고 말씀해
    주세요."라고 하고 기다립니다. 다시 "결제"라고 하면 또 물어봅니다.
  - 네/아니요가 아니면 다시 묻고, 3번 못 알아들으면 멈춥니다(창의 결제하기 버튼은 바로 결제).
 (5) "고른 메뉴 보여줘" → 담은 메뉴 알려주기
  - "고른 메뉴 보여줘", "뭐 담았어?", "장바구니 보여줘", "what is in my cart", "我点了什么" 등
    → "담으신 메뉴는 불고기버거 1개, 콜라 1개입니다. 합계는 …원입니다."(창에도 표시)
 (6) "○○ 빼줘" → 장바구니에서 빼기
  - "콜라 빼줘" → 콜라 모두, "콜라 하나 빼줘" → 1개만, "불고기버거 세트 빼줘" → 세트만.
    "콜라를 뺐습니다." / 없으면 "장바구니에 감자튀김이 없어요."
  - "remove the coke", "去掉可乐"도 됩니다. "콜라 취소해줘"는 이제 콜라만 뺍니다
    (예전에는 장바구니 전체가 비워졌음). "주문 취소"처럼 메뉴 이름이 없으면 전체 비우기.
  - "피클 빼고 불고기버거 주세요"의 '빼고'는 빼기로 보지 않습니다.
 (7) 음성 안내가 쌓여서 늦게 나오던(버퍼링) 문제
  - 모든 문장을 끝까지 읽게 되면서, 메뉴를 빠르게 여러 번 담으면 '○○이 담겼습니다'가
    줄줄이 쌓여 한참 늦게 나왔음.
  - 이제 화면으로 담을 때·음성 주문에 대답할 때·결제가 끝났을 때의 안내는 앞서 밀린 안내를
    끊고 바로 읽습니다(시험: 밀린 4문장 약 20초 → 5초). 이어서 들려줘야 하는 안내
    ('담겼습니다' 다음의 '결제할까요?' 등)는 순서대로 읽습니다.
  - 긴 안내 문구를 줄여 마이크가 빨리 켜지게 함:
    · 시각장애인 안내 질문(약 12.6초) → "안녕하세요. 눈이 불편하시면 네 라고 말씀해 주세요.
      음성으로 주문을 도와드릴게요."
    · 음성 주문 창이 열릴 때(약 16초) → "음성 주문이 시작됩니다. 음성으로는 치킨버거,
      한우버거를 주문하실 수 있어요. 지금 말씀해 주세요."
 (8) 말을 끝까지 듣기
  - 말하다가 0.8초만 쉬어도 말이 끝난 것으로 보고 끊었음 → 1.5초까지 쉬어도 계속 들음.
  - 듣는 동안 소리 기준이 올라가 작게 말한 부분을 '쉬는 중'으로 보던 것을 막음.
  - 한 번에 들을 수 있는 길이 10초 → 15초, '네/아니요' 녹음 3.5초 → 4초.
 (9) 음성 인식률 막대
  - 음성 도움 안내창과 음성 주문 창에 '🎙 음성 인식률' 막대를 넣었습니다. 인식기(Google)가
    들은 말에 매긴 신뢰도를 0~100%로 보여 주고, 아래에 "들은 말: …"을 표시합니다.
  - 80% 이상 초록, 50% 이상 주황, 그보다 낮으면 빨강. 듣는 중에는 "…", 못 들었거나 못
    알아들으면 0%와 이유. (실제 화면 확인: "치킨버거 한 개 줘" → 87% 초록)
  - 콘솔 [음성인식] 줄에도 인식률이 함께 찍힙니다.
 (10) "네/아니요"를 못 알아듣던 문제 → 마이크가 켜질 때 '삐' 소리
  - 로그 분석: 인식이 된 경우는 87~91%로 잘 알아들었지만, 실패한 경우는 질문
    ("…결제할까요? 네 또는 아니요로 말씀해 주세요.", 10~12초)이 끝나기 전에 대답해서
    정작 마이크가 켜진 4초 동안은 조용했음(녹음 소리 평균 36 = 거의 무음).
  - 이제 마이크가 켜지는 순간 '삐' 소리를 내고(음성 안내와 같은 스피커), 질문도
    "삐 소리가 나면 네 또는 아니요로 대답해 주세요."로 끝납니다. 주문을 들을 때도 삐 소리.
  - 못 알아들으면 "다시 한 번 말씀해 주세요." + 삐 소리 뒤에 다시 듣습니다.
  - 화면이 영어여도 한국어 결과를 먼저 봅니다(영어 인식기가 '네'를 'nah'로 받아 적어
    '아니요'로 잘못 판단될 수 있었음. 'nah'는 '아니요'로 보지 않음).
  - 질문을 읽는 도중에 버튼으로 대답하면 남은 질문은 바로 끊고, 창이 닫혔으면 삐 소리도
    내지 않습니다.

12. 판매 메뉴 축소(대회 시연용)
--------------------------------------------------------------
 - 버거는 치킨버거·한우버거 2종만 판매(화면·음성 모두). 불고기·더블 치즈·새우·빅버거는 숨김.
 - 세트 메뉴 없음: 메뉴 화면의 '세트로' 버튼을 숨기고, 음성으로 "세트"라고 해도 단품으로
   담은 뒤 "세트 메뉴는 없어서 버거만 담았어요."라고 알려 줍니다.
 - 사이드·음료는 화면(터치·손동작)으로만 주문. 음성으로 "콜라 주세요"라고 하면
   "사이드와 음료는 음성으로 주문할 수 없어요. 화면에서 골라 주세요."라고 안내합니다.
   (음성으로 "콜라 빼줘"·"고른 메뉴 보여줘"는 그대로 됩니다)
 - 음성 주문 창이 열리면 "음성으로는 치킨버거, 한우버거를 주문하실 수 있어요. 사이드와
   음료는 화면에서 골라 주세요."라고 알려 주고, 예시 문장·안내 문구도 두 버거로 바꿨습니다.
 - 음성 주문 창의 예시 문장 버튼을 없앴습니다(창이 짧아짐). 손을 좌우로 휘두르면 예시가
   입력칸에 채워지던 기능도 없앴습니다(실수로 채워진 예시가 집게 한 번에 주문되는 것 방지).
   창 위쪽의 안내 한 줄은 "예) 치킨버거 줘"로 바꿨습니다.
 - 메뉴 데이터(6종 버거·세트)는 지우지 않고 config.py 설정으로 숨겼습니다. 아래 세 줄만
   바꾸면 원래대로 돌아갑니다(자동 테스트는 전체 메뉴와 대회용 설정을 모두 검사).
     BURGERS_ON_SALE = ("burger_chicken", "burger_hanwoo")   → None 이면 6종 모두
     SET_MENU_ENABLED = False                                 → True 면 세트 사용
     VOICE_ORDER_CATEGORIES = ("burger",)                     → None 이면 음성으로 모두 주문
